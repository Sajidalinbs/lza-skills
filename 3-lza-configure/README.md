# `/lza-configure`

> 📖 **Full playbook:** [`SKILL.md`](SKILL.md) — this README is a summary for browsing.

Translate the signed-off plan into LZA configuration YAML. **Start from the official AWS
baseline** (LZA Universal Configuration), then customize each file — never write the config from
a blank page.

| | |
|---|---|
| **Invoke** | After `/lza-plan` and `/lza-bootstrap` are complete |
| **Predecessor** | [`/lza-bootstrap`](../2-lza-bootstrap/) |
| **Successor** | [`/lza-deploy`](../4-lza-deploy/) |
| **Produces** | A complete, committed config repository |

### What it covers

**Step 0 — seed the repo from the AWS baseline** (`intake/fetch_baseline.sh`), then a per-file
walkthrough with the pitfalls that bite in the field:

| File | Watch for |
|---|---|
| `replacements-config.yaml` | `AcceleratorPrefix` must match the installer stack exactly |
| `accounts-config.yaml` | Emails are permanent and globally unique — generated by the intake planner |
| `organization-config.yaml` | OU names are effectively immutable after deploy |
| `global-config.yaml` | Regions, logging retention, budgets, opt-in regions |
| `security-config.yaml` | Security Hub standards + suppression rules (see `/lza-security-remediate`) |
| `network-config.yaml` | VPCs, subnets, TGW, firewall — snippet generated by the intake planner |
| `iam-config.yaml` | Permission sets, roles, identity-source wiring |
| `customizations-config.yaml` | Anything outside the baseline |

Design stance: no IPAM, no DNS hub VPC, no central interface-endpoints VPC. The accounts,
organization, and network YAML can be generated directly by the [`intake/`](../intake/) planner.
